# Shadow Dev Design — UI 设计大师（布局与交互提案）

视觉与交互决策不靠嘴聊，靠**真 token 高保真视觉稿 + 多构提案 + 小步精修轮**收敛。本技能是 `shadow-dev-propose` 的设计伴侣：propose 负责需求对齐与 Knowledge 查询，本技能在「澄清需求」与「比较方案」之间插入视觉提案轮，产出的设计决策清单由 propose 写入 brief 决策段。也可独立调用，单纯打磨某处布局交互。

**执行纪律：** 视觉稿是本地产物，不写仓库与 GitHub；浏览器自动化只读操作。仓库写操作仍按主流程纪律。

**进场：** 任何操作前，先输出：`▶ [进场] shadow-dev-design · UI 设计提案与打磨`

## 一、设计立场——先立骨法，再谈装饰

接到需求先回答三个问题，答不出就先做第 2 步状态矩阵，不许动手画：

1. **这个项目的设计语言是什么？** 找到项目的文化材料，把通用控件翻译成它的语言。转译是签名动作：进度条 → 白文方印「樂」（印光标悬停微浮、拖拽按印入泥、播放态呼吸晕、本卷最熱曲换「愛」）；溢出标题 → 手卷徐展；开关 → 印章字钮「詞」；列表 → 目次；空态 → 「全体欣赏音乐」印；歌词列 → 界格笺/朱丝栏；弹层收起耳 → 书耳。转译表写在提案开头，实现照表施工。
2. **签名元素是哪一个？** 一个需求只允许一个记忆点（Spend boldness in one place），其余全部安静。签名要在第 3 步每个提案里都以不同形态出现（同一需求内被否决的签名可换构 reincarnate，不可消失）。
3. **我的默认三件套检查：** 奶油底+高反差衬线+赤陶强调 / 近黑底+单一荧光强调 / 报纸细线+零圆角+密排——像模板的方案先自我否决一次再交。

## 二、构图骨架——骨架先于装饰，留白是构图本体

- **先定构图骨架再填装饰**。骨架是信息架构的空间化，候选族：多栏（三栏改良）、对页书（左右页+书脊）、横卷（通栏甲板）、立轴（画左题右）、独奏舞台（单焦点居中）、刻度带+画芯（年谱纵轨）。给每个骨架写一句「定位词」（最文人/密度最高/最空灵/风险最高），让用户按性格挑。
- **信息密度是选择不是默认**：密度谱系两端都要出现在提案里（最空灵 vs 密度最高），中间态是折衷不是答案。
- **视觉配重**：控制件布局用稳定几何——三角锚（两角+居中）、单行钮群（playbar 同构：模式|传输|音量）、通栏底板（全面板公座）vs 左栏私属（漂）。居中构图必须贴底：一团主题色暖晕（radial ≤8% + blur）让浮动元素落在纸面上。
- **留白规则**：留白处必须有构图职责（呼吸/引导/对称轴），纯空 = 没设计完。

## 三、排印与色彩——字是有身体的

- **字体分工**：衬线做签名元素（题名/当前句/题跋/落款），无衬线做操作面与正文，mono 做数据（时间码/序号/题签/数值）。全站三 token，不引入第四族。
- **字距按字汇感知**：CJK 0.1–0.3em 疏排是骨法（眉标/题签/印章字），拉丁文同距即散架——用 `html[lang]` 后代选择器分档（CJK 疏、拉丁密），lang 由站点 i18n 同步保证。
- **色彩纪律**：颜色只走主题 token（禁裸 hex/裸断点）；**唯一饱和元素**原则——面板上只允许一个高饱和件（主播放盘/进度印），其余一律幽灵态（透明描边+hover 显形）；语义色复用（朱砂=当前/激活/品牌，不新增第四种强调色）；明暗双态的暗色淡化走 color-mix，禁反向调色板变量。
- **纸质感配方**（内容浮于材质之上时）：blur 色场（照片退化成色温）→ 纸色罩压平 → feTurbulence 噪点 multiply/soft-light 叠印 → 文字列局部纸罩保对比。

## 四、动效与生命感——每个动效有降级，每个态有承诺

- 运动全部走令牌（`--motion-dur-*`/`--motion-ease-*`），时长落在 150–300ms 交互区间，氛围渐变可至 1.6s。
- **「暂停停走」**：一切随播放运动的元素（跑马灯/等化器/呼吸晕/墨痕）必须与播放态联动，暂停即停。
- **换景渐变**：内容更替用重挂载触发 keyframes 交叠渐变（旧褪新洜 ~1.6s），不做闪切。
- **空间承诺**：控制件在状态切换时**永不挪位**——只有舞台换景（常态/词卷态底排完全同位）。挪位的态切换是交互谎言。
- **reduced-motion**：每个 animation/transition 配瞬切降级；定位一律手动 scrollTo/scrollTop（全文件禁 scrollIntoView——它沿祖先链滚动所有可滚容器，生产实锤把 overflow 壳连带滚走；壳用 `overflow: clip` 使其彻底不可滚）。
- **视觉稿定格**：动画用 `animation-play-state: paused` + 负 `animation-delay` 定格在可读帧，截图才不至于拍到手抖。

## 五、长度自适应策略库——i18n 之后宽度是头号设计约束

任一语言下每个内容位宽度必须有界。策略按序选用：

| 策略 | 适用位 | 要点 |
|------|--------|------|
| 手卷徐展 | 题名/头条 | ghost 量尺测溢出 + 双拷贝轨道 0→-50% 无缝循环；溢出才展、暂停停走、reduced-motion 回落省略号 |
| 单钮循环 | 模式/枚举切换 | 只显示当前值点击循环——宽度从「N 词之和」归零为「单词」 |
| 限宽省略 | 列表行次级文本 | max-width + ellipsis + `title` 全名悬浮 |
| 单句题跋 | 歌词/引文 | 只展示当前句±1，全篇收纳进展开态 |
| 抽屉收纳 | 大列表 | 触发钮参与版面竞宽，抽屉内容不参与 |
| 换行封顶 | 必须多行处 | line-clamp + 展开态承接 |
| 语言钩子 | 字距/排版分档 | `html[lang]` 后代选择器（CJK 疏排/拉丁密排/竖排回退横排） |

交互模式选型同理：**文本枚举宽度不可控时，改单钮循环或图标换装**（图标是跨语言不变量）。

## 六、状态矩阵与态驱动——漏一个态就是返工一轮

- **内容位矩阵**（画图前先列）：每位标注 长度可变性 / 溢出策略 / 交互态全集。矩阵给用户过目后再动手。
- **态全集**：常态、展开、弹层、空态、加载、播放、暂停、拖拽、收起、错误。**空态是设计位不是灰字**（「全体欣赏音乐」印替代死黑）。
- **态驱动免疫机制**：激活/选中/显隐一律**行内样式或行内自定义属性**（JSX style 挂载）——styled 动态类有规则删除竞态、属性选择器有翻转失灵，两连败生产实锤，禁入。条件渲染（mount/unmount）不受限。
- **可访问性全套**：`aria-expanded`/`aria-pressed`/`aria-haspopup`、键盘等价路径（swipe 必配页缘钮）、Escape 分层收起、焦点移入/移回、外点收起、`role='dialog'`+`aria-modal`+滚动锁。
- **既有禁令不回退**：把第 1 步读到的生产禁令逐条对验实现（如 scrollIntoView 禁令、snap 页内手动 scrollTop、印面字符集）。

## 七、提案与迭代法——协作协议

- **一稿多构**：3–4 个**结构互斥**的骨架提案（单构换皮冒充多构 = 禁止），每构 = ASCII 构图 + 一句定位词 + 高保真实现。视觉稿为**单文件静态 HTML**：真 token（从源码调色板/令牌文件取值）、真字体、真实组件 CSS、`?scene=` 参数切场景；本地静态服务 + 浏览器自动化（只读）截图点选。
- **小步精修轮**：用户选中骨架后，每轮只动 **3–5 个可指认改动**（比例/字距/界格/氛围/新交互件），编号列清单先于动手；逐关键态截图回报（常态/展开/弹层）。
- **提词解码表**：`参考 X` = 提取 X 的交互模式、本项目语言转译（不抄视觉皮）；`不喜欢` = 该方向归档留痕（方向名+否决维度）并追问否决维度；`再优化` = 精修轮；`差不多` = 收敛定稿。**否决方向同一需求内不得复活。**
- **常驻预览**：视觉稿一经产出即起本地静态服务（如 `python3 -m http.server <port>`），把 URL 交给用户**自助预览**（`?scene=` 逐场景看），迭代轮改完刷新即见；**截图只做定稿留档**（brief 证据）与浏览器不可用时的替代确认，禁止每轮批量截图轰炸。
- **交付前自批评**：除去一件饰品（Chanel）——每轮收尾删掉最后一个「加了更酷但少了更静」的细节；默写「任何类似需求我会不会做出一样的结果」——会，即模板，重做。

## 八、视觉稿工程规范——视觉稿即规格

- 单文件静态 HTML，零依赖零构建；token 以 CSS 变量注入（值抄自项目源文件并注明出处行号）；每场景一个 `id`，`?scene=` 显隐切换；动画定格参数如上。
- 场景覆盖 = 状态矩阵的视觉化，一态一场景；关键对比（旧版溢出/新版收纳）做对照条。
- **服务交付**：视觉稿目录用固定端口静态服务常驻（复用同一端口便于用户收藏），交付时给「基址 + 场景参数表」而非截图包。
- 实现 = 视觉稿的无损移植：换算（px→token）、类名、动画参数一一对应；实现期发现稿子错漏，先修稿再写码。
- 视觉稿路径与截图链随 brief 留档。

## 九、定稿三件套——与 propose 的接口

1. 视觉稿文件路径（可交互）。
2. 各关键态截图（含否决方向的留档截图）。
3. **设计决策清单**：逐条编号，每条映射 实现文件 + 词典 key + 守卫断言（把新纪律钉进 `style.test` 类门禁，防下个 change 复辟）。

清单由 propose 原样写入 brief 决策与任务。实现期发现稿子错漏：先修稿（本技能短轮）再写码，不静默偏离。

## 提词解码表

| 用户说 | 动作 |
|--------|------|
| 参考 X / 像 X 那样 | 提取交互模式，本项目语言转译，不抄视觉皮 |
| 不喜欢这种布局/设计 | 该方向归档留痕 + 追问否决维度（结构/密度/氛围/细节） |
| 再优化 / 继续打磨 / 不够 | 小步精修轮：先列 3–5 个可指认改动清单再动手 |
| 差不多 / 可以了 / 认可 | 收敛定稿，产三件套，回 propose |
| 开启设计大师 | 本技能全套：状态矩阵 → 多构提案 → 精修轮 → 三件套 |

## 硬规则

- 跳过状态矩阵直接画图，禁止。
- 视觉稿不用项目真 token，禁止——拍板假效果等于零。
- 单构换皮冒充多构，禁止。
- 否决方向原需求内复活，禁止。
- 签名元素超过一个，禁止（Spend boldness in one place）。
- 每轮精修无编号清单禁止；用批量截图轰炸代替常驻预览服务器，禁止。
- 交付前不自批评（除一件饰品 + 模板检查），禁止。
