# 领域模型（Domain Model）

> 规格来自领域模型，不来自测试。测试是证据手段之一；**不变量才是验收对象**。
> 与 `norms/verification.md` 各管验证的一侧：本文件定义「验什么」，`verification.md` 定义「验到什么强度」。

## 为什么

分级验证制撤掉「先写失败测试」的仪式，但没有撤掉「完成必须有证据」。缺的是规格来源：brief 只有任务清单时，验收退化成 diff 走查，谁也说不清「改坏了什么算坏」。领域模型把这一步补上——把必须成立的事实写成不变量，每条不变量绑定一个可追溯观察点。

只取 DDD 的四件概念工具（限界上下文、统一语言、聚合、不变量），**不引入** Entity / Value Object / Repository / CQRS 等战术模式，也不为建模而建模。

## 术语（统一语言，全生态唯一定义处）

| 术语 | 定义 | 判据 |
|------|------|------|
| 限界上下文 bounded context | 一套词汇只有一个含义的边界；跨边界协作必须写明依赖方向与反腐层 | 同一个词在两处含义不同 → 是两个上下文 |
| 上下文地图 context map | 项目内上下文清单与上下游关系，落在 `shadow-docs/domain.md` | 新上下文未登记即视为模型漂移 |
| 聚合 aggregate | 必须整体保持一致的概念单元，有唯一聚合根 | 「改了一半就坏」的东西就是一个聚合 |
| 领域不变量 invariant | 任何时刻都必须成立的断言 | 能用一句「X 必须 Y」表达，且可被观察 |
| 观察点 observation point | 证明不变量成立的真实证据（命令 + 输出 / CI 链接 / 产物扫描结果） | 换个人能照着复现 |
| 领域事件 domain event | 上下文中改变状态、进而改变流程判断的时刻 | 值不值得写进门禁 |

## brief 的「## 领域模型」段

位置：`复杂度评级` 之后、`引用规范` 之前。必填规则：

| 评级 | 要求 |
|------|------|
| **L** | 必填：限界上下文 + 统一语言增量 + **非空**聚合与不变量清单 + 领域事件 |
| **M** | 必填「## 领域模型」段的**最小形态**：一行 `限界上下文`（含上下游）+ 被触及的既有不变量清单（确无则写「无」）；统一语言增量与领域事件可省 |
| **S** | 免填 |

```markdown
## 领域模型

- **限界上下文:** <名称> — <一句话职责>。上游/下游 <关系>；反腐边界 <本上下文不做什么>。
- **统一语言增量:** <新术语及其在本上下文内的唯一含义>（无则写「无」）
- **聚合与不变量:**
  - `<聚合根>`：<必须成立的断言 1>；<必须成立的断言 2>
- **领域事件:** <状态改变时刻及其流程后果>
```

不变量必须是**可观察的断言**，不是目标或愿望。反例「代码结构清晰」；正例「skills 引用的规范文件路径必须存在，死链 grep 归零」。

## 建模动作（propose 的「领域对齐」轮）

1. 这个变更属于哪个上下文？是否同时踩进第二个上下文（是 → 考虑拆 change）。
2. 有没有新词？该词在本上下文里是否已有含义？
3. 哪个聚合的哪条不变量被这次改动威胁？它现在靠什么观察点守住？
4. 是否要求别的上下文跟着变？那就是**跨上下文依赖**，写进 brief 的前置/后继，不顺手改。

## 项目侧上下文地图

每项目一份 `shadow-docs/domain.md`。存在则 propose 必读；不存在且项目含多个上下文时用本模板建：

```markdown
# <项目> 上下文地图

| 限界上下文 | 职责 | 上游/下游 | 主目录或模块 | 关键术语 |
|---|---|---|---|---|
| content | 文章与同步 | ← github → api-v2 | apps/server/src/modules/content | 文章 / 编号 / 同步水位 |

## 术语表增量
- <词>: <本项目内的唯一含义>
```

## 越界禁止

- 不在实现中途新增上下文或改写归属；需要就回 propose 修订 brief。
- 不借「领域建模」扩大改动面：模型只描述本次变更触碰的不变量，不做全仓领域普查。
- 不把实现过程写进上下文地图——地图是长期事实，过程留在 brief。
- 不把横切实践（如 `debugging`）当限界上下文扩写；地图只登记归属与关系，概念定义仍由本文件唯一持有。
- 卡片 `domain` 取值必须来自地图登记名（**domain 值域**）：禁止同义词、中英别名与临时自造——别名会把一个上下文切成两个查询域，路由与查重同时失效。该约束由 `scripts/check-knowledge.mjs` 判定。
- 一个 change 一个主上下文；跨上下文连带改动各自立项。

## 验证方式

- brief 的「## 领域模型」段存在且必填项齐全（L 级不变量清单非空）。
- 每条不变量对应到 `norms/verification.md` 口径下的一个观察点，或在 review 明确记为「未验证」。
- `shadow-docs/domain.md` 登记的上下文与卡片 `scope` 一致；知识卡 `domain:` 值能在地图中找到。
- 实现引入的公开名词（命令、字段、卡片标题）已登记进 brief 术语增量或上下文地图。
