# 信号机制（Signals）

> 信号是**可加权、可衰减、可证伪的指令式微知识**：改变 AI 探索的顺序与停止条件，不替代思考、不减少验证义务。
> 设立动机：实证诊断中大量时间消耗在「知识卡已有排除项但埋没在长文里」与「已证死路反复重走」——信号把这类经验提炼为一句话先验。

## 存放与格式

每项目一份 `shadow-docs/signals.md`（workflow 仓自身的机器/走查级信号也在本仓同名文件）。条目格式：

```markdown
## SGN-<序号> · <一句话指令式陈述（祈使句）>
- 方向: positive | negative
- 权重: 1-5                # 命中累积，cap 5
- 深度: code-read | unit | runtime | field   # 沿用 knowledge-cards 分级
- 域/scope: <技术域 · 目录或业务域>
- 证据: <brief 名或可追溯观察点>
- 命中: <次数>（最近 YYYY-MM-DD）
- 退役条件: <何前提下此信号失效并删除>
```

## 生命周期

| 动作 | 时机 | 规则 |
|------|------|------|
| 创建 | review 的知识写回步骤（与知识卡双评估） | AI 提案；必须带证据与深度标注，无人工门 |
| 加分 | 后续 change 再次命中 | weight +1（cap 5），更新命中日期与证据 |
| 衰减 | >90 天未命中 | weight −1（由 env check 或巡检提示，人工执行） |
| 退役 | weight 归 0，或退役条件成立 | 删除条目 |

## 读取时机与扇宽控制

apply 进入「分析依赖 / 探索」阶段时读取 `shadow-docs/signals.md`，按任务域与 scope 匹配：

| 复杂度评级 | 扇形策略 |
|------------|----------|
| **S** | 不探索，匹配信号直接作为路径 |
| **M** | 正信号排前、负信号跳过对应分支 |
| **L** | 先张满扇形（至少并验两条独立假设），信号仅剪除 weight ≥ 4 且深度为 runtime 的已证死路 |

## 三护栏（防跑偏）

1. **信号排序分支，不消灭验证义务**——高分信号说「先查 X」，不等于查完 X 不验证就收工。
2. **负信号必须深度为 runtime 且带退役条件**——单次失败、单一语境的「勿再走」默认 weight ≤ 2，防止偏见积累。
3. **必须可证伪**——没有退役条件的信号不准入库；前提变化（依赖升级、架构调整）时主动退役。

## 与其他规范的关系

- 深度分级沿用 `norms/knowledge-cards.md` 的 verified-depth。
- 扇宽由 brief 的复杂度评级决定（`norms/tdd-verification.md`）。
- 信号不进 `menu.md` 路由表（路由表只管规范与知识卡；signals.md 由 apply/review 直接读取）。
