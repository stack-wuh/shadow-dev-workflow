# 数据库设计与代码规范

> 适用于 `packages/wuh.site.nest` 中的 MongoDB/Mongoose 持久化代码、同步任务和数据维护脚本。先遵守 [code-style.md](code-style.md) 与 [code-style-backend.md](code-style-backend.md)。

## 数据模型

- 项目数据库使用 MongoDB，服务端通过 Mongoose 8 和 `@nestjs/mongoose` 访问。
- Schema 放在所属业务模块内，不建立绕过模块边界的全局 Model 目录。
- Schema 类、Document 类型和 `SchemaFactory` 结果保持明确命名；已有集合名变更视为数据变更，不能依赖默认推断静默改变。
- 字段必须明确类型、是否必填、默认值、枚举、唯一性和可空语义。
- 对外 API DTO、响应类型与数据库 Schema 分离；不能直接把 Mongoose Document 当作 API 响应契约。

## 集合与索引

- 每个索引必须对应真实查询、排序、唯一性或数据完整性需求。
- 复合索引字段顺序依据过滤条件和排序条件确定，并在变更说明中记录用途。
- `unique` 约束必须考虑历史脏数据和并发写入；不能只依赖应用层“先查再写”。
- 新增高频查询时同步评估索引命中、分页方式和数据量增长；必要时使用 `explain` 验证。
- 删除或修改索引前检查现有查询、写入性能和线上数据影响。

## 查询与写入

- 读取默认使用 `lean()`；只有确实需要 Document 方法、虚拟字段或中间件时才返回 Hydrated Document。
- 列表查询必须有明确分页或数量上限，禁止无边界读取全集合。
- Service 负责数据访问和业务约束，Controller 不直接操作 Model。
- 更新和同步逻辑必须明确幂等键、upsert 条件、重复写入和冲突处理。
- 数据输出在 API 边界转换，不能未经检查暴露内部 `_id`、Document 方法或内部字段。

## 数据变更

- 新增可选字段通常属于兼容变更；删除字段、修改类型、重命名集合或字段属于需要迁移/回填方案的破坏性变更。
- Schema 变更必须评估历史数据、索引、同步任务、API DTO 和所有读取方。
- GitHub Issues 同步、微信读书同步和 seed 脚本必须具备可重复执行语义，或明确执行范围和前置条件。
- 数据库连接、索引创建和迁移失败必须明确报错，不得静默继续启动。
- 生产数据修复脚本必须限制范围，并提供 dry-run 或可重复验证的执行前提。

## 事务与并发

- 涉及多个集合的一致性写入时，先评估是否需要 MongoDB transaction。
- 单文档更新优先使用原子操作，避免“读取后再写入”造成竞态。
- 点赞、评论同步、访问统计等重复请求场景必须明确去重、幂等和最终结果。
- 不为形式引入事务；只有在一致性要求和副作用确实存在时才使用。

## 验证

- 数据模型变更至少检查 Schema 编译、相关 Service 查询、索引定义和 API 边界转换。
- 分页与高频查询验证结果数量、排序稳定性和索引使用情况。
- 同步或维护脚本验证首次执行、重复执行和失败退出行为。
