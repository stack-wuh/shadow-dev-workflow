# TDD 与验证铁律

> 非协商，违反即阻断。

## TDD

- **触发**: 新功能、Bug 修复、复杂重构
- **流程**: 先写能复现失败的测试 → 确认失败 → 写最小实现 → 确认通过
- **阻断**: 没有失败测试记录就开始写实现的，视为未开始

## 验证

- **触发**: 声称 "完成" "通过" "修复" 之前
- **流程**: 运行 Lint + 类型检查 + 相关测试，贴出验证命令和输出
- **阻断**: 无验证输出的完成声明一律视为无效

## 调试

- **触发**: 任何 Bug、异常、测试失败、意外行为
- **流程**: 系统化追溯根因 → 理解为什么出错 → 再修
- **阻断**: 未执行根因分析就改代码的修复，review 阶段直接驳回

## 分支

- **触发**: 任何代码修改操作
- **流程**: 先建功能分支再写代码，main 只接受 merge/PR 合入
- **阻断**: 在 main 上的 commit 直接驳回
