# Monorepo 代码风格约定

> `x.wuh.site` 当前 monorepo 的共同底线。具体包再遵循对应的前端、后端、数据库或共享包规范。

## 适用范围

- `packages/wuh.site.next`：Next.js 15 主站
- `packages/wuh.site.console`：Vite + React 管理端
- `packages/components`：React 组件库
- `packages/hooks`：共享 React Hooks
- `packages/shared-contracts`：前后端共享契约
- `packages/config`：共享类型与配置声明
- `packages/wuh.site.nest`：NestJS 10 API 与服务端脚本
- `packages/docs`：文档预留包

## 渐进式治理

- 新增代码必须遵守本规范及命中的分规范。
- 修改旧代码时，只修正与当前改动直接相关的问题；不以一次变更为全仓改造入口。
- 发现无关的历史问题，记录到 brief 或单独变更，不顺手扩大范围。
- 规范冲突时，以当前代码和可重复验证结果为证据，确认是有意变更、回归还是规范过期。

## 类型安全

- TypeScript 代码禁止新增 `any`；不确定类型使用 `unknown`，并通过类型守卫或校验收窄。
- `as` 只用于类型系统无法表达但已由运行时或边界条件保证的事实；优先使用类型守卫、泛型或明确的 DTO。
- 不为绕过编译器错误而扩大类型、关闭检查或复制不准确的类型。
- 跨包共享的数据类型放入 `@wuh.site/shared-contracts`，不要在消费者中重复定义。

## 命名

- 组件、类和装饰器使用 PascalCase。
- 函数、变量、Hook 和文件内普通成员使用 camelCase；Hook 以 `use` 开头。
- 常量仅在确实表示不可变的模块级常量时使用 UPPER_SNAKE_CASE。
- 布尔变量和返回值使用 `is`、`has`、`can`、`should` 等能表达语义的前缀。
- 文件名遵循所在包的现有约定；新增同类文件必须与相邻文件保持一致，不强求所有包使用同一种命名形式。

## 模块与导入

- Import 顺序为外部依赖、workspace 包、项目别名、相对路径；同组按项目现有 lint/格式化规则保持稳定。
- 不添加未使用 import，不保留注释掉的代码。
- 跨包只能通过 `package.json` 声明的 workspace 依赖和公开入口消费，禁止从其他包的 `src` 或内部文件路径导入。
- 应用包之间禁止互相依赖；主站、管理端和 API 的实现代码不能跨端引用。
- 共享包不能反向依赖应用包。

## 文件职责

- 一个文件应围绕单一职责组织；当文件同时承担多个可独立理解、验证或复用的职责时，应拆分。
- 不以 300 行作为机械门槛；行数只是拆分信号，职责、耦合度、测试难度和变更频率共同决定是否拆分。
- 公共包导出的组件、Hook、函数和类型必须有清晰的接口与命名；公共 API、复杂算法和非显然约束应提供必要说明，不要求为显然代码添加 JSDoc。

## 错误与异步

- 不吞异常，不使用空 `catch`；无法处理的异常继续交给上层边界处理。
- 异步流程必须明确处理成功、失败和取消/清理语义；Promise rejection 不得无主地被忽略。
- 网络超时、重试、鉴权和错误映射只在实际发起外部请求的前端或后端模块中实现，类型包和纯 UI 包不承担这些职责。

## 禁止事项

- 不使用 TODO/FIXME 注释代替已知任务；任务应进入 brief 或独立变更。
- 不为未来场景提前增加抽象、配置或跨包耦合。
- 不顺手重写无关代码、注释或格式。
