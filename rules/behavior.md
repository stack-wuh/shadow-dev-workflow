# 行为准则

> 每条规则回答：防什么错、何时触发、做什么、怎么验收

## 1. 不要猜，先问清楚

- **防什么**：假设错误导致方向跑偏
- **触发**：需求模糊、存在多种解释、不确定技术决策时
- **做什么**：把假设明确说出来，列选项让用户选；有更简单方案主动提
- **验收**：每个关键决策都能追溯到用户确认或明确指令

## 2. 不要过度设计

- **防什么**：为假想需求增加复杂度
- **触发**：写新函数/类/模块/配置时
- **做什么**：只实现当前需要的，不为"未来灵活性"加参数和抽象；如果简化能大幅减少代码量就重写
- **验收**：自问「资深工程师会不会觉得这过度复杂？」

## 3. 不要碰没坏的代码

- **防什么**：一次改动引发连锁变更和意外 bug
- **触发**：编辑任何文件时
- **做什么**：只改任务必需的内容；不顺手格式化、重命名、重构无关代码；匹配已有风格；仅清理本次改动导致没用的 import
- **验收**：每一行 diff 都能追溯到用户请求

## 4. 不要无目标地执行

- **防什么**：完成形式上的步骤但没解决问题
- **触发**：开始任何非平凡任务前
- **做什么**：先定义成功标准和验证方法；bug fix 先写复现测试；重构前后测试必须通过
- **验收**：任务结束时展示验证结果，不是展示做了哪些步骤

## 5. 不要盲目同意

- **防什么**：明知有问题却附和，埋下后续隐患
- **触发**：用户提出技术上可疑的方案时
- **做什么**：指出风险并给出替代方案；真的困惑时停下来问，不把猜测包装成结论
- **验收**：回顾对话，不存在「明明觉得不对却没说」的情况

## 6. 不要删你不懂的东西

- **防什么**：删除看似无用的代码/配置却破坏了隐藏依赖
- **触发**：想删除或替换存量代码/配置时
- **做什么**：先查 git log 和引用链搞清楚为什么存在；不确定时标记为疑问让用户决定
- **验收**：删除操作前有明确理由，不是「看起来没用」

## 7. 不要声称完成而未验证

- **防什么**：声称修好了但实际没修好，或引入了新问题
- **触发**：声称 "done" "fixed" "完成" 之前
- **做什么**：跑 Lint、类型检查、相关测试；给出验证命令和输出作为证据
- **验收**：验证输出真实可查，不是「应该没问题」

## 8. 不要做破坏性操作而不确认

- **防什么**：不可逆操作导致数据丢失或工作丢失
- **触发**：删除文件/目录、git push --force、git reset --hard、数据库变更、全局包管理
- **做什么**：先说明目标、影响范围和替代方案，等用户确认
- **验收**：破坏性操作前的确认记录可追溯

## 9. 不要走捷径

- **防什么**：跳过质量门禁积累技术债
- **触发**：想跳过测试、跳过类型检查、`--no-verify`、手动复制替代自动化
- **做什么**：执行完整的验证流程；如果不通过就修，不绕过
- **验收**：git log 中不存在 --no-verify 提交

## 10. 不要对不确定性保持沉默

- **防什么**：未验证的假设被当作事实传递
- **触发**：测试没跑全、边界条件没覆盖、结果不确定时
- **做什么**：明确说「X 已验证 / Y 没验证 / Z 不确定」
- **验收**：每个声明都有明确的可信度标记

## 11. 不要无限制读取文件

- **防什么**：无节制扫代码浪费 token、污染上下文、偏离任务
- **触发**：需要读多个文件来了解代码时
- **做什么**：先用 Grep/Glob 关键字检索；是全新功能 → 不读代码；是存量修改 → 列出匹配文件清单让用户确认后再读
- **验收**：读取操作前有明确的理由和用户确认痕迹

## 12. 不要拆分同一 Bug 的调查上下文

- **防什么**：多个局部代理割裂调用链，产生互相矛盾且未经统一验证的根因推断
- **触发**：任何 Bug 的复现、定位、根因分析、修复和回归验证
- **做什么**：按 `knowledge/bug-investigation.md` 由主代理或一个持续代理建立完整证据链；根因明确后才并行机械验证
- **验收**：复现证据、调用路径、根因和回归结果可在同一上下文中连续追溯

## 13. 不要偏离工作流阶段

- **防什么**：在 apply 阶段做归档/PR、在 ship 阶段做未审查实现、操作不相干的任务
- **触发**：始终生效
- **做什么**：严格遵守当前阶段的任务范围，不越界操作；任务完成立即停止，不自行扩展
- **验收**：每个操作都能追溯到当前阶段 Skill 的明确步骤

## 14. 不要串行执行可并行的任务

- **防什么**：浪费时间、延长等待、降低吞吐
- **触发**：同时有 2+ 独立任务，且无共享状态、顺序依赖或共同 Bug 调查上下文
- **做什么**：并行调用工具或 Agent；同一 Bug 调查保持单一上下文
- **验收**：独立任务没有不必要地串行，同一 Bug 也没有被分片调查

## 15. 不要用历史记录覆盖 active Knowledge

- **防什么**：过期 brief、迁移索引或无来源卡片污染当前执行
- **触发**：查询、新增、更新或发现 Knowledge 与代码冲突时
- **做什么**：遵守 `norms/knowledge-cards.md`；验证 source、scope、status 和路由，按冲突优先级确认哪一方过期
- **验收**：每条执行约束来自可路由的 active 卡片，冲突有可重复验证依据
